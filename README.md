> A potentiometer simulates a sensor value; it is streamed via Kinesis to S3; an OLED shows the current value.

**Docker producer (EC2) → Amazon Kinesis → AWS Lambda → Amazon S3 → Web dashboard**

## 1. Overview

The project idea is a physical producer: a potentiometer generates a sensor value, an OLED shows the current value, and the value is streamed through Kinesis into S3. A real ESP32 setup needs hardware, wiring and a physical network connection, so this implementation removes that dependency. **No physical hardware was used**: the potentiometer value is generated by code, and the "OLED" is a text display printed in the terminal. A Python program running in a Docker container on Amazon EC2 **simulates** the sensor, prints a **virtual OLED display** in the terminal, and sends each reading to the cloud. The cloud side is serverless: Kinesis buffers the stream, Lambda processes it, S3 stores it, and a browser dashboard visualizes it.

It demonstrates the complete path of IoT data: **generation → ingestion → processing → storage → visualization**.

## 2. Objectives

- Simulate an ESP32 potentiometer sensor and OLED display in software.
- Package the producer as a portable Docker image.
- Stream JSON telemetry into Amazon Kinesis Data Streams.
- Process records automatically with an event-driven AWS Lambda function.
- Store processed batches as JSON objects in Amazon S3.
- Show the latest reading, status and a trend chart in a live web dashboard.
- Avoid hardcoded credentials and control cloud cost.

## 4. How the Data Flows

1. **Generate** – `sensor_producer.py` picks a random reading between 10.0 and 95.0 every 2 seconds, classifies it, and prints a Virtual OLED block.
2. **Ingest** – the reading is sent to Kinesis with `put_record` (partition key `sensor-partition-1`); the first 20 characters of the shard sequence number are logged.
3. **Process** – Kinesis triggers `ProcessKinesisSensorData`. It base64-decodes each record, parses the JSON, and adds a `processed_at` Unix timestamp.
4. **Store** – all records of one invocation are written as a single JSON array to `incoming-data/sensor_batch_<unix-time>_<8-char-request-id>.json`.
5. **Visualize** – `index.html` lists the objects under `incoming-data/`, downloads the newest one, and displays its last record. It refreshes every 3 seconds.

## 7. Data Format and Status Thresholds

Record sent to Kinesis by the producer:

```json
{
  "device_id": "SIMULATED_ESP32_01",
  "sensor_value": 61.08,
  "status": "NORMAL (MEDIUM)",
  "timestamp": 1794028992
}
```

Record as stored in S3 (Lambda adds `processed_at`). Each S3 object is a JSON **array** of such records:

```json
[
  {
    "device_id": "SIMULATED_ESP32_01",
    "sensor_value": 61.08,
    "status": "NORMAL (MEDIUM)",
    "timestamp": 1794028992,
    "processed_at": 1794028994
  }
]
```

| Status | Condition | Dashboard value colour |
|---|---|---|
| NORMAL (LOW) | value < 35 | Blue |
| NORMAL (MEDIUM) | 35 ≤ value ≤ 75 | Green |
| WARNING (HIGH) | value > 75 | Red |

The simulated reading is a random value between **10.0 and 95.0** (2 decimal places). The dashboard chart axis is fixed at 0–100.

## 8. Component Details

### 8.1 Producer (`sensor_producer.py`, `Dockerfile`)
- Base image `python:3.11-slim`; installs `requirements.txt`, copies the script, runs `python -u sensor_producer.py` (`-u` makes output unbuffered so the OLED display appears immediately).
- Region `us-east-1` and stream name `sensor-data-stream` are set in the script. **No credentials are in the code**; boto3 reads them from the environment.
- Failures are caught and printed (`Error sending payload: ...`), so a temporary error does not stop the loop.
- Runs until stopped with `Ctrl + C`.

### 8.2 Kinesis stream
- Name `sensor-data-stream`, Provisioned mode, 1 shard.

### 8.3 Lambda (`lambda_function.py`)
- Function `ProcessKinesisSensorData`, trigger: Kinesis event source mapping (enabled).
- Decodes base64 payloads, adds `processed_at`, writes one batch file per invocation with `ContentType: application/json`, and logs `Stored N records into S3 bucket: ...`.
- Uses the default execution role (LabRole in Learner Lab); no keys in code.

### 8.4 S3 storage
- Bucket `sensor-stream-data-2503a51075`, objects under `incoming-data/`.
- Example key: `incoming-data/sensor_batch_1794027675_91ee8d5a.json`.

### 8.5 Dashboard (`index.html`)
- Cards: current value with status, device ID and last-updated time. Below them a Chart.js line chart of the last ~15 readings.
- Every 3 seconds it calls the S3 list API (`?list-type=2&prefix=incoming-data/`), takes the **last key in the listing** as the newest file, fetches it, and shows its last record.
- The browser reads S3 directly with no credentials, so the bucket must allow public read of `incoming-data/` and CORS GET (see Step 5 below).

## 9. Setup and Deployment

### Prerequisites
- AWS Academy Learner Lab (region `us-east-1`) or an AWS account
- EC2 instance (Amazon Linux) with network access

### Step 1 – Kinesis
Create the stream `sensor-data-stream` (Provisioned, 1 shard).

### Step 2 – S3 bucket
Create bucket `sensor-stream-data-2503a51075` (or your own name, and then change `BUCKET_NAME` in `lambda_function.py` and `index.html`).

### Step 3 – Lambda
1. Create function `ProcessKinesisSensorData` (Python 3.x) with the lab execution role.
2. Paste `lambda_function.py` and click **Deploy**.
3. Add `sensor-data-stream` as a trigger and keep it enabled.

### Step 4 – EC2 and Docker
```bash
sudo yum install -y docker git
sudo systemctl start docker
sudo usermod -aG docker ec2-user   # log out and in again
```

### Step 5 – Allow the dashboard to read S3
Turn off "Block public access" for the bucket (only acceptable because the data is simulated), then add a policy and CORS rule like these. Match them to what you actually configured.

Bucket policy:
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicListIncomingData",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:ListBucket",
      "Resource": "arn:aws:s3:::sensor-stream-data-2503a51075",
      "Condition": { "StringLike": { "s3:prefix": "incoming-data/*" } }
    },
    {
      "Sid": "PublicReadIncomingData",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::sensor-stream-data-2503a51075/incoming-data/*"
    }
  ]
}
```

CORS:
```json
[
  {
    "AllowedHeaders": ["*"],
    "AllowedMethods": ["GET"],
    "AllowedOrigins": ["*"],
    "ExposeHeaders": []
  }
]
```

### Step 6 – Build the image on EC2
```bash
git clone https://github.com/<your-username>/<your-repo-name>.git
cd <your-repo-name>
docker build -t iot-producer:v1 .
```

### Step 7 – Run the producer
Pass credentials at runtime only (copy them from the Learner Lab *AWS Details* panel):

```bash
docker run --rm --name iot-producer-container \
  -e AWS_DEFAULT_REGION=us-east-1 \
  -e AWS_ACCESS_KEY_ID="<YOUR_ACCESS_KEY_ID>" \
  -e AWS_SECRET_ACCESS_KEY="<YOUR_SECRET_ACCESS_KEY>" \
  -e AWS_SESSION_TOKEN="<YOUR_SESSION_TOKEN>" \
  iot-producer:v1
```

These credentials expire when the lab session ends.

### Step 8 – Open the dashboard
Open `index.html` in a browser on any device with internet access.

## 13. Security Notes

- No credentials in source files or in the Docker image; they are injected with `-e` at runtime.
- Do not commit `.env` files or keys. Add a `.gitignore` containing `.env` and `*.pem`.
- The dashboard needs **public read** on `incoming-data/`. This is acceptable for simulated data only. For real data, put the dashboard behind authentication (for example CloudFront with signed access or an API).
- In a normal AWS account, give Lambda a least-privilege role (read Kinesis, write only to `incoming-data/`).

## 14. Cost Control and Cleanup

1. `Ctrl + C` in the EC2 terminal to stop the container (`--rm` removes it).
2. Delete the Kinesis stream (it bills per shard-hour) and disable the Lambda trigger.
3. Stop the EC2 instance.
4. Empty the S3 bucket if you no longer need the data.

## 15. Troubleshooting

| Problem | Likely cause and fix |
|---|---|
| `ExpiredToken` / `UnrecognizedClientException` | Learner Lab credentials expired. Copy fresh ones. |
| `ResourceNotFoundException` | Stream name or region wrong (`sensor-data-stream`, `us-east-1`). |
| `permission denied` running docker | Run `sudo usermod -aG docker ec2-user` and log in again. |
| No files in S3 | Lambda trigger disabled, or the role cannot write to the bucket. Check CloudWatch logs. |
| Dashboard stays on `--.--` | Bucket policy or CORS missing, "Block public access" still on, or wrong bucket name in `index.html`. Check the browser console. |
| Dashboard stops updating after a while | See limitation 4 below. |

## 16. Limitations

1. Sensor data is simulated, not from real hardware.
2. One device, one shard: limited throughput.
3. Learner Lab credentials are temporary, and lab resources reset between sessions.
4. The dashboard takes the last key of a single S3 list call, which returns at most 1,000 objects in alphabetical order. After about 1,000 batch files it will keep showing an old file. Delete old objects, or add an S3 lifecycle rule or pagination, to fix this.
5. The dashboard polls S3 every 3 seconds instead of receiving pushed data, so there is a small delay.
6. The dashboard bucket is publicly readable (see Security Notes).
